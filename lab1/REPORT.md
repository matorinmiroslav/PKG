ЛАБОРАТОРНАЯ РАБОТА № 1
Цветовые модели

Цель работы
Изучить основные цветовые модели RGB, CMYK, HSV, HLS, XYZ и CIELAB (Lab), принципы перехода между цветовыми пространствами, понятие цветового охвата (gamut) и проблему отображения цветов, не входящих в диапазон sRGB. Освоить разработку интерактивного графического приложения, позволяющего выбирать и изменять цвет, одновременно отображая его представления в трёх заданных цветовых моделях: RGB, Lab и CMYK.

Задачи работы
В ходе выполнения лабораторной работы были поставлены следующие задачи:
• Изучить назначение и область применения цветовых моделей RGB, CMYK, HSV, HLS, XYZ и Lab.
• Рассмотреть математические преобразования между цветовыми пространствами.
• Изучить понятие цветового графика МКО, цветового охвата и выхода цвета за границы отображаемого диапазона.
• Реализовать кроссплатформенное десктопное приложение на базе фреймворка PyQt6 с одновременным отображением RGB, Lab и CMYK, а также выводом предупреждения при ограничении цвета до доступного диапазона sRGB.
• Подготовить исполняемый файл приложения (.exe) для демонстрации преподавателю.

Использованные средства разработки
• Python 3 — основной язык программирования для реализации логики приложения.
• PyQt6 — библиотека для построения графического интерфейса пользователя (GUI).
• PyInstaller — утилита для сборки исходного Python-кода в независимый исполняемый файл (.exe).
• Модули math и sys — стандартные библиотеки Python для математических вычислений и взаимодействия с системой.

Ход выполнения работы

1. Разработка графического интерфейса (UI)
Было создано десктопное приложение на базе класса QMainWindow. Интерфейс разделен на логические блоки с использованием контейнеров компоновки QHBoxLayout и QVBoxLayout:
• Верхняя панель содержит рамку предварительного просмотра цвета (QFrame), кнопку вызова системной палитры (QPushButton) и текстовое поле для вывода предупреждений о выходе за gamut (QLabel).
• Нижняя часть содержит три независимые панели для управления компонентами моделей RGB, LAB и CMYK.
Для каждого параметра цвета динамически формируется строка управления, состоящая из подписи (QLabel), ползунка (QSlider) для плавного изменения и числового поля (QSpinBox для целых чисел, QDoubleSpinBox для дробных с точностью до 0.1). Сигналы ползунков и полей ввода взаимно связаны.

2. Визуальный выбор цвета
Для интеграции стандартного инструмента выбора цвета использован класс QColorDialog. При нажатии на кнопку «Выбрать из палитры» открывается системное диалоговое окно. Выбранный цвет возвращает RGB-компоненты (red, green, blue), после чего запускается централизованный механизм пересчета всех моделей.

3. Реализация математических преобразований цветов
Для обеспечения точных переходов между пространствами были реализованы следующие алгоритмы:
• RGB ↔ CMYK: Пересчет выполняется по классическим формулам с выделением компоненты чистого черного цвета (K) и нормированием каналов от 0 до 100%.
• RGB → LAB: Прямой перевод невозможен, поэтому в модуле converter реализован транзит через аппаратно-независимое пространство XYZ. На этапе RGB → XYZ применяется линеаризация (декомпрессия гаммы) по стандарту sRGB, после чего координаты XYZ переводятся в LAB относительно точки белого D65 (95.047, 100.000, 108.883).
• LAB → RGB: Выполняется обратная цепочка LAB → XYZ → RGB с последующей гамма-коррекцией.

4. Автоматический пересчёт и защита от зацикливания
Для синхронизации панелей реализованы три обработчика событий: on_rgb_changed, on_lab_changed и on_cmyk_changed. Чтобы избежать бесконечной рекурсии (когда изменение одной модели вызывает обновление второй, а та снова обновляет первую), внедрен флаг блокировки self.is_updating.
Сквозной пересчет координируется функцией update_all_from_rgb:
• При изменении RGB: вычисляются LAB и CMYK, обновляются все виджеты.
• При изменении LAB: вычисляется RGB с флагом проверки диапазона, затем обновляются остальные данные.
• При изменении CMYK: вычисляется RGB, на основе которого обновляются все панели.

5. Проверка диапазонов и предупреждение о выходе за gamut
Пространство LAB способно описывать цвета, физически не воспроизводимые на мониторах sRGB. В функции обратной конвертации lab_to_rgb реализован алгоритм контроля цветового охвата. Если вычисленные значения R, G или B выходят за пределы, они принудительно ограничиваются методом обрезки (clamping), а функция возвращает флаг out_of_gamut = True. В этом случае на верхней панели приложения мгновенно загорается красное предупреждение: «Выход за границы sRGB! Выполнена обрезка.».

6. Компиляция в исполняемый файл (.exe)
Для выполнения требований к сдаче работы скрипты были скомпилированы в один автономный бинарный файл с помощью команды:
pyinstaller --noconsole --onefile main.py

Проблемы, возникшие в работе, и способы решения

1. Бесконечная рекурсия сигналов (зацикливание интерфейса).
Причина: Изменение значения в QSpinBox программно сдвигало QSlider, что вызывало повторный сигнал изменения и приводило к зависанию программы.
Решение: В класс приложения добавлен логический флаг-предохранитель self.is_updating, который блокирует обработку сигналов во время выполнения функции общего обновления.

2. Сильные искажения цветов при переходе LAB ↔ RGB.
Причина: Попытка линейного перевода без учета гамма-коррекции монитора.
Решение: В алгоритм конвертации внедрена функция линеаризации (pivot) sRGB-компонент перед переводом в XYZ и обратное степенное преобразование при возврате в sRGB.

3. Несоответствие шага ползунка для дробных значений LAB и CMYK.
Причина: Компонент QSlider в PyQt6 работает исключительно с целыми числами (int), тогда как параметры LAB и CMYK требуют точности до десятых долей.
Решение: Диапазон слайдеров был сопоставлен с диапазоном целых чисел, а дробная точность реализована на стороне QDoubleSpinBox. Синхронизация значений выполнена через приведение типов функцией int().

Результаты работы
В результате выполнения лабораторной работы создано десктопное приложение Color Converter, которое:
• Одновременно отображает и пересчитывает компоненты цвета в моделях RGB, LAB и CMYK.
• Предоставляет удобный интерактивный интерфейс (слайдеры, точный ввод, системный Color Picker).
• Точно обрабатывает математические переходы через опорные координаты пространства XYZ.
• Визуально предупреждает пользователя о потере цветовых данных при выходе за пределы охвата sRGB.
• Скомпилировано в работоспособный, автономный файл формата `.exe`.

Вывод
В ходе лабораторной работы были изучены ключевые цветовые модели и математические принципы переходов между ними. На практике было установлено, что аппаратно-зависимые (RGB, CMYK) и аппаратно-независимые (LAB) пространства не могут быть связаны напрямую, что потребовало реализации промежуточного шага трансформации через координаты XYZ с применением линеаризации sRGB. Использование объектно-ориентированного подхода на Python и библиотеки PyQt6 позволило создать отзывчивый интерфейс с автоматическим пересчетом в реальном времени. Требование по предоставлению готового исполняемого `.exe` файла полностью выполнено.
