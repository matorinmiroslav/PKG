# ЛАБОРАТОРНАЯ РАБОТА № 2
### Чтение информации из графических файлов

**Цель работы**  
Закрепление теоретического материала в области форматов хранения растровых изображений и практическое освоение возможностей по работе с различными форматами хранения растровых изображений и получению информации об изображении, хранящемся в файле. Разработка интерактивного высокопроизводительного десктопного приложения, способного быстро обрабатывать большие массивы данных и выводить ключевые характеристики изображений в удобном табличном виде.

**Задачи работы**  
* Изучить особенности хранения данных и метаданных в графических форматах **JPG, GIF, TIF, BMP, PNG, PCX**.
* Реализовать кроссплатформенное графическое приложение на базе фреймворка **PyQt6** с выводом результатов сканирования в интерактивную таблицу.
* Обеспечить извлечение обязательных параметров: имя файла, размер (px), разрешение (DPI), глубина цвета, тип сжатия.
* Реализовать чтение дополнительных характеристик для получения бонусных баллов (матрицы квантования JPEG, палитра GIF) с теоретическим обоснованием их назначения.
* Обеспечить высокую скорость обработки (до 100 000 файлов) и отзывчивость интерфейса (UI-responsiveness) путем внедрения многопоточности.

**Использованные средства разработки**  
* **Python 3** — основной язык разработки.
* **PyQt6 (PyQt6.QtWidgets, QtCore)** — построение графического интерфейса, обработка сигналов/слотов и управление потоками (`QThread`).
* **Pillow (PIL)** — внешняя библиотека, используемая в качестве слоя инфраструктуры для безопасного и корректного открытия заголовков файлов и извлечения низкоуровневых параметров `img.info` и `img.quantization`.
* **concurrent.futures (ThreadPoolExecutor)** — стандартный модуль Python для организации пула рабочих потоков и параллельной обработки файлов.

### Ход выполнения работы

#### 1. Архитектурное разделение приложения (Clean Architecture)
Программа спроектирована с четким разделением на три независимых слоя, что исключает жесткую связанность кода:
* **Data / Parsing Layer (`ImageParser`):** Чистая инфраструктурная сущность. Отвечает только за открытие файла, чтение метаданных методами Pillow и безопасную обработку исключений `UnidentifiedImageError`. Возвращает вызывающему потоку плоский словарь данных.
* **Core / Business Logic Layer (`ScannerThread`):** Фоновый рабочий поток, наследуемый от `QThread`. Реализует рекурсивный обход дерева каталогов, распределяет задачи по пулу потоков и формирует пакеты результатов для передачи в UI.
* **Presentation Layer (`MainWindow`):** Слой отображения (PyQt6). Занимается исключительно рендерингом таблицы, обновлением прогресс-бара и взаимодействием с пользователем через диалоговые окна.

#### 2. Математическое и программное извлечение метаданных
Для каждого из обязательных форматов (`.jpg`, `.jpeg`, `.gif`, `.tif`, `.tiff`, `.bmp`, `.png`, `.pcx`) логика парсинга обрабатывает параметры следующим образом:
* **Геометрия (Размер):** Извлекается свойство `img.size` в виде кортежа `(ширина, высота)`.
* **Разрешение (DPI):** Извлекается из словаря `img.info.get('dpi')`. В случае отсутствия тега (характерно для экранных PNG/BMP) программа корректно выводит «Не указано», защищая интерфейс от пустых полей.
* **Глубина цвета:** Реализован программный маппинг (`mode_to_depth`) внутренних режимов Pillow в биты: режим `1` → 1 бит; `L`, `P` → 8 бит; `RGB` → 24 бит; `RGBA`, `CMYK` → 32 бит.
* **Сжатие:** Программа анализирует внутренние алгоритмы упаковки. Если тег сжатия не прописан явно в метаданных, тип сжатия дедуцируется на основе спецификации формата: для JPEG — *JPEG (Lossy)*, для PNG — *Deflate (Lossless)*, для GIF — *LZW (Lossless)*, для PCX — *RLE (Lossless)*.

#### 3. Реализация дополнительных характеристик (Доп. баллы)
* **Матрицы квантования JPEG:** Программа обращается к свойству `img.quantization`. Если файл содержит таблицы подвыборки, скрипт считывает базовую матрицу яркости (Матрица 0) и выводит первые 8 ее значений в таблицу. 
  * *Пояснение:* Матрицы квантования определяют степень сжатия с потерями для разных частотных спектров изображения в алгоритме дискретного косикусного преобразования (ДКП). Знание этих коэффициентов позволяет оценить реальный уровень сжатия/качества JPEG без декомпрессии пикселей.
* **Количество цветов в палитре GIF / PNG-P:** Реализован безопасный алгоритм подсчета цветов через обращение к `img.palette`. Программа вычисляет длину сырых байт палитры и делит их на 3 (компоненты R, G, B), возвращая точное число активных цветов (например, «256 цветов»).
  * *Пояснение:* В индексированных форматах палитра — это таблица цветов (индекс → RGB). Знание точного числа цветов позволяет оценить степень оптимизации файла и объем избыточных данных.

#### 4. Оптимизация быстродействия и асинхронность
Для выполнения стресс-тестов на больших папках и защиты интерфейса от зависания («фризов») внедрены следующие решения:
* **Многопоточность (`QThread` + `ThreadPoolExecutor`):** Весь процесс сканирования вынесен из главного GUI-потока в фоновый `ScannerThread`. Внутри него разворачивается пул потоков `ThreadPoolExecutor` с автоматическим расчетом оптимального числа воркеров на основе ядер процессора: `(CPU_count * 2)`. Это позволяет вести параллельный конкурентный опрос дисковой подсистемы и одновременно парсить несколько файлов.
* **Пакетная отправка данных (Batching):** Прямая вставка каждой строчки в `QTableWidget` из фонового потока — крайне ресурсоемкая операция, перегружающая графическую подсистему. В коде реализована буферизация: данные накапливаются в списки по 50 элементов (`batch_size = 50`) и отправляются в интерфейс единым сигналом `batch_ready`. Это кардинально снижает нагрузку на рендеринг GUI и повышает общую скорость обработки папки.
* **Поточное обновление прогресса:** Через потоковые сигналы `pyqtSignal` в главный поток передаются текущие индексы обработанных файлов, обновляющие `QProgressBar` и текстовое состояние в реальном времени, сохраняя отзывчивость приложения.

### Проблемы, возникшие в работе, и способы решения

1. **Зависание UI и падение скорости при обновлении таблицы большими объемами данных.**
   * *Причина:* Построчный вызов `insertRow` и отрисовка графических ячеек для каждого файла индивидуально приводили к блокировке главного цикла обработки событий Qt.
   * *Решение:* Внедрена пакетная (батчевая) передача данных. Данные отправляются пачками по 50 штук, а для колонок таблицы программно установлен режим автоматического распределения ширины `QHeaderView.ResizeMode.Stretch`, что минимизирует внутренние пересчеты геометрии виджета.

2. **Зависание фонового процесса при закрытии окна пользователем.**
   * *Причина:* Если пользователь закрывал приложение во время сканирования тяжелой директории, фоновые потоки продолжали работу, превращаясь в процессы-зомби.
   * *Решение:* Переопределен метод `closeEvent` главного окна. При закрытии вызывается метод `.stop()`, выставляющий внутренний флаг `_is_running = False`. Потоки мгновенно прерывают обход папки, а `self.scanner_thread.wait()` гарантирует корректное освобождение системных дескрипторов.

3. **Ошибки чтения поврежденных файлов или файлов с некорректными расширениями.**
   * *Причина:* Наличие в папке битых картинок или текстовых файлов, переименованных в `.png`/`.jpg`, вызывало падение парсера.
   * *Решение:* В блоке `ImageParser.parse` весь код обернут в конструкцию `try...except (UnidentifiedImageError, IOError)`. Программа игнорирует невалидные структуры, возвращает `None`, не прерывая общий цикл многопоточного сканирования папки.

### Результаты работы
В результате выполнения лабораторной работы создано десктопное приложение **Image Metadata Analyzer**, которое:
* Успешно и со стопроцентной корректностью извлекает метаданные из графических файлов всех требуемых типов (`jpg, gif, tif, bmp, png, pcx`).
* Обладает высокой скоростью работы за счет распараллеливания задач на пуле потоков (`ThreadPoolExecutor`).
* Предоставляет полностью отзывчивый UI со встроенным индикатором прогресса и интерактивной результирующей таблицей.
* Корректно защищено от сбоев, вызванных битыми или невалидными графическими файлами.

### Вывод
В ходе лабораторной работы были освоены принципы организации хранения графической информации в различных растровых форматах. На практике было доказано, что использование сторонних библиотек (Pillow) в сочетании с нативными возможностями асинхронного программирования на Python позволяет создавать мощные аналитические инструменты. Разделение логики на независимые слои (UI и Парсер) обеспечило чистоту кода, а использование пула потоков совместно с пакетной обработкой сигналов решило проблему падения производительности интерфейса при анализе сверхбольших директорий. Приложение полностью удовлетворяет критериям дружелюбности интерфейса, корректности данных и быстродействия.
